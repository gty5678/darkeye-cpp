## 工作区说明

## 必须保持的边界

1. `public.db` 与 `private.db` 的表、字段、关系和版本迁移。
2. `data/settings.ini` 的既有键和值格式。
3. 浏览器插件访问的 `127.0.0.1:56789` HTTP 接口。
4. 外部信息补充器 `127.0.0.1:56790` 的客户端协议。
5. 封面、人物图片、剧照、快捷键和工作区布局的数据格式。

## 安全规则

- 开发和自动测试只使用脱敏副本。
- 新旧程序不得同时写同一数据库。
- 正式迁移前必须确保 Python 版正常退出，并先备份数据库。
- 不复制 SQLite 的 `-wal`、`-shm` 文件作为迁移手段。

## 已确认的基线缺陷

Python 仓库的 `initPublicTable.sql` 在 `actress_name` 的两个外键约束之间缺少逗号，无法直接用于新建空公共库。C++ 仓库中的独立副本仅修复该 SQL 语法错误，不改变表结构。

历史 `initPrivateTable-v1.0.sql` 同时写入了 `1.0` 和 `1.1` 两条版本记录，与文件名和旧表唯一约束不符。C++ 测试 fixture 移除错误的 `1.1` 记录，用于真实验证 `1.0 → 1.1` 迁移。

历史公共库升级脚本会删除 `db_version` 表但不重建。C++ 迁移器在脚本成功后补建版本表并记录版本 `2`；`PRAGMA user_version` 仍是版本判断的首要来源。

历史私有库 1.0 SQL 使用了无效的 `UNIQUE INTEGER` 列声明顺序。测试 fixture 修正为等价的 `INTEGER UNIQUE`，仅用于还原其预期旧约束。
